# T-0027: Make the formalization process history independently readable

**Status**: IN_PROGRESS | **Size**: L
**Phase**: -

## Context

The process history reconstructs causal proof-development arcs and distinguishes
accepted artifacts from task records and session evidence. It nevertheless names
Wotan, Project Control, Codex session traces, and local record types before a reader
outside this environment has been told what they are or why they matter.

## Acceptance Criteria

- [ ] Add an early, self-contained account of Lean, mathlib, Lake, Git, Codex,
  Wotan, Project Control, and the observable session trace.
- [ ] Explain each local tool first by its general methodological function and only
  then give its project-local name.
- [ ] Define task, gate, owner decision, evidence record, accepted state, and session
  prefix before relying on those terms.
- [ ] Keep the report a causal methodological history rather than a software setup
  guide or chronological task diary.
- [ ] Preserve the evidence ledger, privacy boundary, correction history, and
  distinctions among local, architectural, mathematical, and audit failures.
- [ ] Compile and freeze the revised PDF under the existing stable filename.
- [ ] Inspect every rendered page and correct all content and layout defects.

## Verification Plan

### Hard Endpoints

- [ ] `latexmk` - the report compiles without unresolved references or citations.
- [ ] `pdfinfo`, Ghostscript, and `pdftotext -layout` - the PDF is structurally valid
  and contains all intended sections without placeholders.
- [ ] Render every page with Poppler and inspect the complete PNG set.
- [ ] Verify all evidence identifiers and repository paths against retained records.

### Manual Checks

- [ ] A reader given only the process-history PDF can understand every local system
  needed by the main argument.
- [ ] The new orientation material explains roles without endorsing tool records as
  mathematical proof evidence.
- [ ] The report remains distinct from the scientific report.

### Risks

- A glossary can become inert front matter; connect each definition to the type of
  historical claim it can and cannot support.
- Reflow can break long tables, diagrams, and evidence pagination.

## Approach

Insert a project-environment and vocabulary section before the evidence taxonomy,
then revise first mentions throughout to use tool-neutral descriptions. Retain local
paths and detailed record identifiers in evidence-oriented passages and appendices.

## Implementation Notes

T-0026 fixed the scientific report's explanatory boundary. This report can now
define the project environment without duplicating the scientific Lean primer.
