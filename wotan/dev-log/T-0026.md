# T-0026: Revise the scientific report for Lean pedagogy and provenance

**Status**: DONE | **Size**: L
**Phase**: -

## Context

The first scientific report is mathematically coherent and explicit about the trust
boundary, but its deliberately minimal Lean introduction does not show a non-Lean
reader how an informal paper claim becomes a precise theorem contract and a checked
proof. Its source-to-endpoint appendix also does not make sufficiently visible in the
main narrative which mathematics comes directly from the paper, which is required
formal infrastructure, and which results were strengthened, specialized, or added by
the formalization.

## Acceptance Criteria

- [x] Add a compact, accurate Lean primer that assumes no prior Lean knowledge.
- [x] Follow at least one headline result from paper statement through mathematical
  contract, Lean types and assumptions, theorem declaration, proof structure, build,
  and axiom audit.
- [x] Explain definitions, theorem declarations, typeclass assumptions,
  noncomputability, tactics, proof terms, imports, and kernel checking only to the
  depth needed to read this project.
- [x] Introduce explicit provenance categories for direct paper claims,
  formalization choices, strengthenings, concrete realizations, and excluded claims.
- [x] Apply those categories to every major mathematical layer without overstating
  novelty.
- [x] Preserve the source-audited theorem statements, model boundary, and accessible
  scientific narrative.
- [x] Compile and freeze the revised PDF under the existing stable filename.
- [x] Inspect every rendered page and correct all content and layout defects.

## Verification Plan

### Hard Endpoints

- [x] `lake build` - the referenced Lean corpus remains fully checked.
- [x] Three `pdflatex` passes - the report compiles without unresolved references or citations.
- [x] `pdfinfo`, Ghostscript, and `pdftotext -layout` - the PDF is structurally valid
  and contains all intended sections without placeholders.
- [x] Render every page with Poppler and inspect the complete PNG set.
- [x] Check all quoted Lean declarations against the compiled source files.

### Manual Checks

- [x] A mathematically mature reader can explain what Lean checks and how one source
  claim reaches a public endpoint after reading only the report.
- [x] The paper/formalization boundary is visible in the main text rather than only
  recoverable from an appendix.
- [x] Added formal results are described as contributions of this formalization, not
  automatically as literature novelty.

### Risks

- Added pedagogy can interrupt the mathematical narrative; keep a single running
  example and a compact vocabulary.
- Provenance labels can conflate verification status with source origin; define them
  as two independent classifications.
- New tables may create pagination or width defects; render after every substantial
  typesetting change.

## Approach

Use double rejection as the running example because its source proof, mathematical
contract, Lean endpoint, helper architecture, and axiom status are all fully audited.
Add a separate contribution map covering subspaces, cones, approximation, signals,
NNLS, occupancy, and population realization.

## Implementation Notes

Project Control records the approved revision in `PCR-2026-08-05-001` and
`PCD-2026-08-05-001`.

The report now distinguishes verification status from provenance. Two early tables
define the provenance vocabulary and map every major layer into paper content versus
formalization additions. Short provenance paragraphs repeat that distinction where
each layer is discussed. Double rejection supplies one continuous example from paper
notation through closure-safe definitions, an exact theorem signature, tactic-level
proof structure, elaboration, imported facts, and kernel certification.

The reusable workflow also exposed a missing repository-level claim index.
`FORMALIZATION-CLAIMS.md` now records the source, provenance, Lean endpoint, delta,
evidence, and audit status of twelve principal claim families.

## Obstacles

The first provenance-map table floated onto an otherwise sparse page. Converting it
to an in-flow numbered table placed the map next to its explanation and allowed the
mathematical narrative to continue normally.
