# T-0023: Write the scientific formalization report

**Status**: DONE | **Size**: L
**Phase**: -

## Context

After the source audit and any resulting corrections, produce a self-contained
technical report about the mathematics and its machine-checked verification. The
reader may be mathematically sophisticated but must not need prior Lean expertise.
The report is not a chronology of project activity and must not expose task-management
machinery as part of the scientific argument.

## Acceptance Criteria

- [x] Write a polished English LaTeX report with a clear title, abstract,
  introduction, mathematical notation, references, and conclusion.
- [x] Explain the CNS model and formal problem decomposition independently of Lean
  syntax, then introduce only the minimum proof-assistant concepts needed to
  understand the certification claim.
- [x] Present the principal exact theorems, hypotheses, proof ideas, and mathematical
  relationships in a coherent thematic order.
- [x] Distinguish exact deductions, conditional approximation bounds, modeling
  interfaces, and empirical/biological claims throughout the report.
- [x] Give an auditable coverage account tied to the source-traceability record,
  including limitations and statements intentionally not verified.
- [x] Explain the trusted base and axiom audit in terms accessible to a non-Lean
  specialist without overstating what machine checking establishes.
- [x] Keep workflow chronology, Wotan, task ids, and implementation diary material
  out of the main scientific narrative.
- [x] Compile the LaTeX source to a stable PDF under `output/pdf/`, render every page,
  and correct all content, typography, pagination, table, figure, citation, and
  accessibility defects found in visual and textual QA.

## Verification Plan

### Hard Endpoints

- [x] LaTeX compilation completes without unresolved references or citations.
- [x] PDF metadata and page count are valid; extracted text contains all sections and
  no placeholders.
- [x] Every rendered page passes visual inspection at readable resolution.
- [x] Mathematical claims and theorem names agree with the audited Lean state.

### Manual Checks

- [x] A reader unfamiliar with Lean can understand what was proved and under which
  assumptions.
- [x] The prose reads as a scientific report, not as a sequence of implementation
  actions.
- [x] Limitations are concrete and balanced rather than boilerplate caveats.

### Risks

- Exhaustive coverage can make the report encyclopedic. Use thematic synthesis,
  summary tables, and appendices while preserving precise traceability.
- Lean terminology can obscure the mathematics. Translate theorem content into
  conventional notation and reserve code identifiers for traceability aids.

## Approach

Organize around the model's mathematical layers: geometric cone identities, finite
optimization and convergence, signal operators and dynamics, probabilistic occupancy,
and the boundary between theorem and biological interpretation. Use the audited source
map and public Lean endpoints as evidence. Include proof sketches that reveal why the
results hold, not tactic transcripts.

stable report-class header removed that ambiguity.
